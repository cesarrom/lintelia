# 0010 — `bun e2e`: one command makes the end-to-end suite happen

`bun e2e` (`scripts/e2e.ts`) replaces the previous ways of running the suite (`bun run e2e` against a running stack,
`bun run stack:test`, `e2e:watch` / `e2e:headless`, which remain as aliases):

| Situation | `bun e2e` |
| --- | --- |
| every service of the e2e profile answers | attaches (`--attach` asks for exactly that and never starts anything) |
| nothing answers | starts the whole stack in the background, runs, stops it after (`--keep` leaves it) |
| the stack's supervisor is still starting (or restarting) services | waits for it |
| partially up | **error** listing what is up and down — start the whole stack yourself and re-run, or `bun e2e --force` |
| `--force` | stops the stack and every process on its ports, starts everything again, runs |

Headed or headless is decided from the machine (display + a browser with a UI → windows you can watch), unless
`--headed` / `--headless`; API-only runs need no browser. Warnings before the run: Playwright's Chromium missing, a
busy machine. Any other argument goes to Playwright (`--grep @FIA-04`, a file, `--project=api`, `--retries=1`). A full
run rewrites docs/testing/flow-status.md; filtered runs do not. The exit code is Playwright's.

Documentation: [docs/testing/e2e.md](../testing/e2e.md#running-the-suite), TESTING.md §4, readme.md.
